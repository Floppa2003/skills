## 1. Практический маршрут доступа

1. **Сначала сохранить точную цель:** URL канального поста, отдельный `comment=`, автор/дата, ожидаемый тип файла. Не удалять `comment=` и затем объявлять файл поста файлом комментария.
2. **Публичный текст:** читать конкретную первичную страницу/Telegram embed/полную подпись Instagram. Поисковый сниппет — кандидат; отсутствие индекса/ошибка одного инструмента не доказывает отсутствие поста/профиля.
3. **Публичный Telegram-файл:** обычная форма https://telegramdownloader.net/ru/ → точный обычный URL поста → «Получить ссылку» → «Скачать файл» → штатный экран/таймер → видимая кнопка готового файла. Практически сработало для PDF /323, девяти исходных видеопостов и Jana /374. Если ожидается обсуждение, проверять сообщение и содержимое отдельно.
4. **Комментарий/вложение обсуждения:** использовать уже разрешённую пользовательскую сессию официального https://web.telegram.org/a/ . Открыть пост → обсуждение → нужное сообщение → **контекстное меню вложения → Download**. Обычный клик PDF первоначально не дал подтверждённой загрузки. Для доказательства источника — `Copy Message Link` у того же сообщения; для /323?comment=446 интерфейс вернул точную пользовательскую ссылку. Если вход недоступен, использовать штатный доступ/экспорт пользователя, не обходить ограничения.
5. **Instagram Reel:** полная первичная подпись/теги отдельно от ролика; через обычную форму https://saveclip.app/ru9/instagram-reels-video-download получить видимую ссылку готового видео, скачать байты. Практически получены 4 старых+3 новых Reels. Временные media-URL не сохранять в публичный skill; сохранять исходный Reel URL.
6. **Проверить файл:** фактическое имя, байты, тип/контейнер, открытие PDF или декодирование видео, длительность/разрешение, SHA-256; сравнить версии при одинаковых именах. Просмотреть весь документ или распределённые кадры и отдельно ключевые экраны. Китайское имя/запрос сверять по кадру, не только ASR.
7. **Отметить предел:** Т/Р/К/И/Ф, просмотренные страницы/кадры/комментарии, нерасшифрованное аудио, неопределённая привязка файла к посту. Внешний транскрипт не означает просмотр видео. Копии полных чужих транскриптов/документов и самих медиа не включать в публичный skill.

Telegram-ссылка `https://t.me/shopping_in_chinaaa/323?comment=446`: **323 — пост канала, 446 — сообщение связанной группы обсуждения**. Номер корня ветки может отличаться от номера канального поста. `/shopping_in_chinaaa/446` не является проверенной заменой. Первичные правила: https://core.telegram.org/api/links#message-links ; https://core.telegram.org/method/messages.getDiscussionMessage (пользовательские сессии, API в успешном маршруте не вызывался); https://core.telegram.org/widgets/discussion . Виджет `https://t.me/shopping_in_chinaaa/323?embed=1&discussion=1` раньше вернул Site Unavailable; поздний успех Telegram Web отменяет вывод об отсутствии обсуждения, но не историю неудачного маршрута.

## 5. YouTube, первичные подписи и ограничения извлечения

- Firecrawl не выполнил 3 независимых Telegram scrape и 1 Instagram search из-за исчерпанных кредитов; повторы не делались, доступны были другие публичные средства. Это ограничение инструмента, не доказательство закрытия источника.
- Никакого автоматического обещания скачивания «любого файла из любых комментариев»: подтверждены конкретные ветки 323/339. Исходные 4 nastia не раскрыты; 28 прочих исходных обсуждений не прочитаны; /652 ожидает точный ID; /601,/9 имеют нераскрытые дополнительные медиа. Новое расширение не включает чтение всех комментариев.

## 6. Что хранить при новом запуске

Минимальная запись: `canonical_source_url`, `channel_post_id`, `discussion_message_id` отдельно, дата публикации/проверки, язык/регион, тип Т/Р/К/И/Ф, filename/байты/MIME/длительность/SHA 256, просмотренные страницы/интервалы, извлечённые запросы/имена/URL, конкретные ограничения. Секреты, cookies, авторизованные сессии, временные подписанные download URL, персональные складские реквизиты и полные чужие тексты не публиковать. Имена файлов и канонические публичные URL сохранять для воспроизводимости; приватные копии/Library-ID — отдельная закрытая карта.
